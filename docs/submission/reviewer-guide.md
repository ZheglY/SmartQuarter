# Проверка Умного Квартала в MAX

## Действующий демонстрационный доступ

Состояние проверено 29 сентября 2026 года:

- Бот: https://max.ru/t365_hakaton_max_bot.
- Дом: **ПИК**, **Ул. Александры Монаховой д99 к4**. В поиске достаточно слова «Монаховой».
- Председатель этого дома: **Дима** — рассматривает заявки на вступление.
- Администратор платформы: **Yaro / Ярослав Жегль** — назначает председателей и одобряет новые дома.

Это не общедоступные логины с паролем. Каждый проверяющий входит своим аккаунтом MAX.
Контакт ответственного участника команда передаёт организаторам в закрытой карточке
сдачи вместе со временем проверки. Перед сдачей Ярославу нужно заполнить этот контакт:
публичной ссылки на его профиль в данном документе пока нет. Написать боту — не значит
автоматически сообщить администратору о необходимости председательского доступа.

1. Откройте ссылку бота в MAX и нажмите кнопку запуска/«Начать», если она отображается.
2. Откройте мини-приложение кнопкой бота. Не открывайте сайт отдельно во внешнем браузере:
   для входа нужны подписанные данные запуска из MAX.
3. В **Профиле** проверьте своё имя и MAX ID. Скопируйте MAX ID для организаторов/команды.
4. Откройте **Мои дома → Найти дом**, найдите «ПИК» по адресу и отправьте заявку.
5. Дима открывает **Мои дома → Управление домом → Заявки жильцов** и принимает заявку.
   До принятия ожидается статус ожидания и отсутствие доступа к содержимому дома.
6. После принятия вернитесь в список домов и нажмите **Выбрать дом** у «ПИК».
   Главная и профиль должны показывать роль **Житель**. Откройте проблемы, новости,
   сообщество, календарь и контакты. Настройки и профиль доступны из нижней навигации.

Дом «ПИК» подходит для просмотра. Новые записи, управление ролями и автоматический
DATA-API выполняйте в отдельном доме, описанном ниже. Его создание ещё нужно выполнить
через интерфейс: эта инструкция не означает, что он уже появился на сервере.

## Председательский доступ без снятия Димы

Рекомендуемый дом для проверки: **Техническая проверка MAX**. Передайте его точное
название, учебный адрес и UUID в закрытой карточке приёмки после создания.

1. Проверяющий, который будет председателем, сначала входит через бота MAX.
2. Ярослав открывает **Профиль → Администрирование платформы**, находит его по MAX ID
   и нажимает **Разрешить регистрацию домов**. Это пока только разрешение на регистрацию,
   а не управление домом «ПИК».
3. Проверяющий открывает **Мои дома → Зарегистрировать дом**, вводит название
   «Техническая проверка MAX» и явно вымышленный учебный адрес.
4. Ярослав в **Рассмотреть регистрации домов** одобряет заявку.
5. Проверяющий выбирает новый дом. На главной и в профиле должна быть роль
   **Председатель**; доступны заявки жильцов, контакты и управляющие действия.
6. Два других проверяющих входят через MAX, находят новый дом и подают заявки.
   Новый председатель принимает их. Это автор заявки и сосед, подтверждающий её.

Если тестовый дом уже создан, Ярослав выбирает пользователя кнопкой **Назначить
председателем дома**, затем выбирает именно тестовый дом и подтверждает назначение.
У дома один председатель: прежний станет жителем этого дома. Не выбирайте «ПИК» для
временного доступа жюри. Административный доступ проверяющим для основного сценария
не требуется. Назначение/снятие администратор показывает отдельно на тестовом доме.

## Сценарий проверки (три аккаунта)

Все три пользователя выбирают один тестовый дом. Используйте префикс `[Проверка]`
и демонстрационную фотографию из репозитория, не реальные персональные данные.

| Кто | Действие | Ожидаемый результат |
|---|---|---|
| Житель A | Главная → Сообщить о проблеме; добавить JPEG/PNG, категорию, описание и место | Новая заявка в своём доме, фотография открывается |
| Житель B | Открыть эту заявку и подтвердить | Одно подтверждение; повтор не увеличивает счётчик |
| Житель A | Открыть свою заявку | Надпись об уже отправленной заявке; нет управления статусом или генерации заявления |
| Председатель | Открыть заявку и сформировать заявление | Непустой черновик с адресом, описанием и количеством подтверждений; можно скопировать |
| Председатель | Пройти статусы до решения | История обновляется; статус виден жителю. «Отправлено» — ручная отметка, фактической отправки из приложения нет |
| Председатель | Создать объявление | Жители видят его в «Новостях» |
| Председатель / житель | Создать опрос с будущим сроком / проголосовать | Голос учитывается один раз, результаты доступны; после закрытия голосование запрещено |
| Председатель / житель | Создать и изменить событие / открыть месяц события | Событие видно в календаре; у жителя нет кнопок изменения |
| Житель A / B | Предложить инициативу / поддержать | Одна поддержка; председатель может завершить инициативу |
| Председатель | Добавить демонстрационный контакт службы | Житель видит контакт; после архивации он исчезает из активного справочника |
| Все | Профиль → Контакты служб → Назад | Возврат в профиль; нижняя панель не теряется |
| Все | Открыть уведомление о новом опросе/инициативе | Кнопка ведёт к соответствующему объекту; каждый голос не порождает уведомление |

Для проверки уведомлений пользователь должен запустить бота и разрешить уведомления
в настройках приложения. Не все события уведомляют каждого участника: настройки и
действующее членство в доме учитываются. Уведомление может появиться после фоновой
обработки outbox.

## Автоматические тестовые данные

**Без участия оператора:** `docker compose -f deploy/test/compose.yaml run --build --rm test`.
Стенд сам создаёт синтетические аккаунты, дома, фото и записи в отдельных БД,
исполняет workflow и DATA-API. Он не предназначен для входа через реальный MAX.

**На работающем сервере:** однократно подготовить реальный тестовый дом и три роли через
шаги выше. Далее [исполнитель DATA-API](../../tools/data-api/README.md) добавляет контент
через обычный API, без доступа к БД, приватному ключу сервера и токену бота.
Реальный вход MAX и одобрение членства не заменяются подделкой пользователя.

После прогона в доме останутся учебная решённая заявка, заявление, объявление, закрытые
опрос и инициатива. Проверочное событие удаляется. Обновляйте cookie повторным входом
через MAX: срок сессии по умолчанию 12 часов. Новые пользователи, дома и роли этим
исполнителем не создаются и не изменяются.

## Что передать организаторам закрыто

- Итоговый commit SHA, ссылку бота, адрес API, контакт команды и время доступности.
- Название/адрес/UUID выделенного дома; порядок допуска трёх проверяющих.
- Для HTTP-проверок: свежие `sq_session` трёх ролей и способ получить их повторно.
- Согласованный внешний S3-шаг DATA-API либо команду запуска нашего исполнителя.
- Рабочие параметры окружения только при необходимости собственного развёртывания.
  Для проверки готового API bot token и ключи S3 не требуются.
