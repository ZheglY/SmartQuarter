# Что исправить в SmartQuarter.pdf перед сдачей

1. **Первый слайд:** заменить `https://github.com` на
   `https://github.com/ZheglY/SmartQuarter`. Вместо `32 commits history` указать результат
   `git rev-parse HEAD` после последних изменений и их фиксации. Не оставлять старый SHA.
2. **Доступ для проверки:** вместо названий ролей Resident/Chairman дать ссылку бота,
   способ входа своим MAX, точный тестовый дом, ответственных за принятие заявок и
   назначение председателя, контакт команды и порядок получения свежей API-сессии.
   Свериться с [инструкцией](reviewer-guide.md). Тестовый дом ещё требуется подготовить.
3. **Первый слайд, smoke-тест:** исправить «создание карточки дома» на «создание заявки
   с фотографией». Добавить подтверждение другим жителем и изменение статуса председателем.
4. **Первый слайд, секреты:** техническую версию с необходимыми рабочими параметрами
   передавать организаторам закрыто. В публичной версии убрать токен бота и облачные ключи.
   Если действующий секрет уже опубликован, заменить его. Для проверки готового API
   нужны пользовательские сессии, а не bot token.
5. **Название:** выбрать единое «Умный Квартал / SmartQuarter» вместо чередования
   «СмартКвартал» и «Умный Квартал».
6. **Слайд 3:** исправить «в госудраственном мессенджеры» на «в мессенджере MAX».
7. **Слайд 4:** подписать шаги под телефонами: «Заявка с фото», «Подтверждение соседом»,
   «Черновик заявления», «Контроль статуса». Мелкий текст скриншотов не заменяет подписи.
8. **Слайд 5:** опросы и объявления уже реализованы. Перенести их из будущего расширения
   в текущие возможности; добавить календарь, инициативы и управление ролями/домами.
9. **Эффект:** добавить ожидаемые метрики пилота — время подготовки обращения, доля
   заявок с актуальным статусом, участие жителей. Не выдавать целевые значения за измеренные.
   «Подтверждённую пользовательскую ценность» подкрепить пилотом или обозначить целью.
10. **Ограничения, данные и источники:** заявление отправляет председатель вручную;
    один председатель на дом; MAX и S3 — внешние зависимости; примеры и фотографии
    демонстрационные. Указать источники документации MAX, формат DATA-API и стек.

Архитектура и команда уже представлены. Формат продуктовых слайдов рекомендательный:
не нужно добавлять отдельный слайд на каждый пункт. Технический первый слайд должен
давать воспроизводимый доступ.
