## Найденные блокирующие проблемы

1. Gateway `unhealthy`, внутренний `/readyz` возвращает 503. Точная зависимость,
   не проходящая проверку Gateway, пока не установлена; остальные HTTP readiness
   отвечают 200, что само по себе не подтверждает готовность их gRPC-соединений.
2. В запущенном Gateway и `/home/ubuntu/SmartQuarter/deploy/server/.env` остаётся
   `MAX_BOT_USERNAME=smart_quarter_bot`; фактический бот — `t365_hakaton_max_bot`.
3. `GET /subscriptions` возвращает пустой список. Команда `/start` отправлена
   через MAX и видна в чате; автоматического ответа за время проверки не получено.
4. Сертификаты добавлены в Ubuntu, но CA-бандл запущенного Gateway не доверяет
   сертификату MAX API. Проверка TLS с извлечённым из контейнера бандлом завершилась
   `CERTIFICATE_VERIFY_FAILED`. Проверка TLS не отключалась.
5. Работают старые контейнеры: Gateway запущен 23 сентября, Identity/Community/Mini App
   — 22 сентября. Код в checkout уже на `549b708`, но запущенные компоненты не обновлены.
6. `/api/v1/houses/search`, `/api/v1/notifications/settings`,
   `/api/v1/house/service-contacts` возвращают 404. В отдаваемом JS нет нового
   маршрута регистрации домов. Identity содержит только `users`, `houses`,
   `memberships`, `goose_db_version`; в Community нет `service_contacts`.
   Миграции нового workflow не применены.
7. `ADMIN_USER_IDS` не заполнен. Реальный пользователь успешно вошёл, но Mini App
   показывает отсутствие активного членства и старый экран обращения к председателю.

## Что требуется перед полным приёмочным прогоном

Сначала сохранить резервные копии PostgreSQL и серверной конфигурации, проверить
предусловия миграций по [руководству](../house-workflow/README.md).
Затем применить обновление сервисов и Mini App из текущего checkout, передать
доверенные CA в Gateway, исправить имя бота в серверном `.env`, проверить готовность
и зарегистрировать webhook `https://maxhack.ru/webhooks/max` с совпадающим секретом.
Назначение администратора платформы выполняется по проверенному внутреннему UUID.

После обновления повторить реальные сценарии: регистрация/одобрение дома,
вступление, приглашение, контакты, проблема с фото, заявление, объявления,
передача роли, отзыв доступа и уведомления. В этой проверке они не выполнялись:
необходимые новые API/схемы отсутствуют. Успешного полного приёмочного прогона
развёрнутого приложения пока нет.
