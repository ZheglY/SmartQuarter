# Проверка CI и исходников — 26 сентября 2026

## Причина сбоя

В [запуске 36268823511](https://github.com/ZheglY/SmartQuarter/actions/runs/36268823511)
шаг `Application workflow` завершился до выполнения тестов:
`storage-init Error unauthorized: access to the requested resource is not authorized`.
Образ `quay.io/minio/mc:RELEASE.2025-08-13T08-35-41Z` недоступен для загрузки.
Проверка образа сервера MinIO также вернула `no such manifest`.
Остальные 11 заданий прошли; общий статус `CI` упал вслед за `Application workflow`.

В тестовом Compose сервер и клиент S3 теперь собираются из официальных исходников
MinIO. Версии не изменены: в Dockerfile закреплены SHA исходных release-коммитов,
в образы скопированы лицензии. См. [официальное описание сборки](https://github.com/minio/minio#source-only-distribution).
Рабочее S3-хранилище приложения этим изменением не затронуто.

При проверке обнаружены и исправлены устаревшие ожидания сквозных тестов:

- вместо четырёх сообщений по заявке ожидаются два важных уведомления;
- все четыре доменных события должны публиковаться и обрабатываться;
- дедупликация проверяется на событии изменения статуса после подтверждения обработки;
- повторный webhook должен отправлять ровно одно сообщение независимо от числа
  ранее отправленных уведомлений;
- проверка нового опроса ожидает актуальный текст сообщения.

## Проверка

На чистом изолированном стенде успешно выполнены:

- сборка сервера и клиента MinIO из закреплённых исходников;
- сборка Identity, Issue, Community и тестового Gateway;
- пять полных сценариев заявок с реальными PostgreSQL, Redis и S3;
- сценарии регистрации дома, заявок на вступление, приглашений, передачи роли,
  админки, контактов, опросов, календаря, инициатив и ограничения доступа;
- проверка создания и повторного обновления участия, сохранения профиля,
  отзыва доступа и отказа в неизвестной роли через `check-provision.sh`.

Реальный MAX заменён HTTP-приёмником тестовых сообщений. Рабочие пользователи,
данные и сервисы удалённого сервера в этих тестах не используются.

## Исходники и ветки

До исправления сервер и GitHub `feat/house-identity-service` имели один коммит
`85a7b4c555bfffa7b42ff944c8dcc98af3db5f63` и дерево
`34df2a2f73426f84b7c479a385e35638b511e40d`; рабочая копия сервера была чистой.
GitHub `main` находился на `b1ae96a`: два последующих коммита представлены
в [PR №26](https://github.com/ZheglY/SmartQuarter/pull/26).
Проверка совпадения относится к отслеживаемым исходникам, а не к секретам `.env`,
сертификатам, данным БД или собранным Docker-образам.

Ветка исправлений развёртывания переименована в `feat/fix-ci-deployment-guide`
локально и на GitHub с сохранением её последнего удалённого коммита.
Служебные описания подготовки иллюстраций удалены из актуальной документации;
пометки о демонстрационном характере изображений сохранены. История коммитов
и обязательные заголовки генераторов контрактов не переписывались.
